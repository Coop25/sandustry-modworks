Release safely

Publish once. Update the same item forever.

A release is more than clicking Upload. Preserve the mod’s internal ID, Workshop identity, preview asset, and update metadata so users receive upgrades instead of duplicate items.

01 / Package

Preflight checklist

  • modinfo.json parses as strict JSON and uses manifest/API version 1.
  • The manifest’s entry, optional workerEntry, overrides, patches, maps, and assets all exist inside the folder.
  • preview.png is a readable regular PNG file.
  • The internal id is stable and namespaced.
  • The release version and description match the actual change.
  • The mod loads in a clean game session and its important behavior is exercised.
  • Any bundle patch still matches exactly the expected number of locations.

Keep development-only tests and notes outside the package folder. The Workshop upload should contain only files the mod needs.

02 / First release

First Workshop upload

  1. Copy the complete mod folder into Sandustry’s local mods directory.
  2. Launch Sandustry through Steam so Workshop services and ownership are available.
  3. Open Mods, choose Create mods, select the local mod, and verify its preview and description.
  4. Click Upload. Complete the Steam Workshop agreement if Steam asks.
  5. After success, confirm that the game created workshop.json in the local mod folder.
  6. Back up that generated file with the rest of the mod source.

03 / Identity

Why workshop.json matters

{
  "schemaVersion": 1,
  "publishedFileId": "3785874614"
}

The numeric publishedFileId links one local folder to one Steam Workshop item. Sandustry uses it to show the local mod’s Open button and to update the existing item.

Never casually delete or recreate this file. Uploading without it can create a new Workshop item instead of updating the old one. The Steam account performing an update must own the linked item.

modinfo.json identifies the mod inside Sandkit. workshop.json identifies the published Steam item. They solve different problems and neither replaces the other.

04 / Updates

Updating safely

  1. Make and test the change in source control.
  2. Increment the manifest version.
  3. Update the description or changelog without changing the internal mod ID.
  4. Confirm workshop.json still points to the intended Workshop item.
  5. Copy the complete updated folder to the local mods directory.
  6. Launch through the owning Steam account and upload from Create mods.
  7. Open the item page and verify the visible version, notes, and preview.

For compatibility-sensitive changes, state the tested Sandustry build and call out any bundle patches so users know what may need retesting after a game update.

05 / Troubleshooting

Common publishing failures

SymptomLikely cause
No Open buttonThe local record has no valid publishedFileId, usually because workshop.json is missing or invalid.
Steam unavailableThe game was not launched through Steam, Steam is offline, or Workshop services are unavailable.
Item not foundThe ID in workshop.json no longer resolves.
Not ownedThe current Steam account does not own the linked Workshop item.
Preview missing/invalidpreview.png is absent, unreadable, outside the folder, or not a regular file.
Mod changed after startupThe local mod’s identity changed while Sandustry was running; restart before uploading.
Patch rejectedThe current game bundle no longer matches the patch’s expected count.

Keep workshop.json with the mod source.

Practical guides

From empty folder to working mod.

These guides explain the boundaries that matter: what belongs in the manifest, which thread owns a change, how to mutate the simulation safely, and when a patch is justified.

01 / Foundation

Your first mod

A Sandustry mod is a folder with a modinfo.json manifest and one or more resources. Start with the smallest possible main-thread mod, confirm that it loads, then add one capability at a time.

mods/
└── first-mod/
    ├── modinfo.json
    ├── main.js
    ├── preview.png
    └── assets/

Minimal manifest

{
  "manifestVersion": 1,
  "id": "yourname.first-mod",
  "name": "My First Mod",
  "version": "1.0.0",
  "apiVersion": 1,
  "entry": "main.js",
  "description": "A small first Sandustry mod.",
  "author": "Your name",
  "dependencies": [],
  "loadOrder": 0
}

Minimal entry

await (async () => {
  "use strict";

  const api = sandkit.api;
  api.ui.toast("My First Mod loaded");
})();

Why the async wrapper? Sprite loading returns a promise. Using one async entry pattern from the beginning lets you safely await api.sprites.loadFromMod(...) later.

  1. Put the folder in the local mods directory opened by Sandustry.
  2. Launch through Steam, enable the mod, and restart if prompted.
  3. Confirm the toast appears and check the game’s mod diagnostics if it does not.
  4. Add one feature, reload, and test again.

02 / Identity

Manifest fields

FieldPurpose
manifestVersionFormat version for modinfo.json. Current local examples use 1.
idStable internal identity. Use a namespaced value such as author.mod-name; do not change it after release.
versionYour release version. Semantic versions make update history easier to understand.
apiVersionSandkit API contract requested by the mod. The documented surface is version 1.
entryMain-thread JavaScript entry. Usually main.js.
workerEntryOptional code loaded in manager and simulation workers.
dependenciesOther mod IDs that must load first.
loadOrderOrdering hint when several mods affect related content.

The manifest can also declare configOverrides, textureOverrides, asset providers, and a custom map. Keep paths relative and inside the mod folder.

03 / Runtime boundaries

Main entry vs worker entry

main.js

Use the main entry to register content, load sprites, update definitions, add UI, register tech, schedule triggers, and request simulation changes. Mutation methods commonly end in WhenIdle because the simulation may currently be running elsewhere.

worker.js

The worker entry runs in manager and simulation worker contexts. Its API is deliberately smaller, but simulation mutation methods are direct: createAtCell, moveBetweenCells, damageAtCell, and similar calls.

Do not assume an API exists in both contexts. Use the API explorer’s Main and Worker filters. Main-only UI, sprite-loading, registration, and publishing-adjacent logic should not be placed in worker.js.

Safe main-thread mutation

api.world.runWhenSimulationIdle(() => {
  api.elements.replaceAtCellWhenIdle(cellX, cellY, sandType);
});

When a dedicated *WhenIdle method exists, call it directly. Use the explicit idle callback when several related operations need one safe boundary.

04 / Structures

Registering a structure

await api.sprites.loadFromMod("example-machine", "assets/machine.png");

api.structures.register({
  id: "example-machine",
  name: "Example Machine",
  description: "A compact 2 × 2 machine.",
  categoryKey: "logistics",
  order: 50,
  shape: [
    [1, 1],
    [1, 1]
  ],
  render: {
    imageName: "example-machine",
    size: { width: 10, height: 10 },
    offset: { x: -1, y: -1 },
    z: 0.85,
    ui: { outline: true, width: "10px", height: "10px" }
  }
});

The shape determines occupied cells. The render definition is visual only; keep its size and offset aligned with the grid footprint.

Periodic processors

api.structures.addProcessor("example-machine", {
  intervalMs: 50,
  process(structure, processor) {
    const sourceX = structure.x;
    const sourceY = structure.y - 1;
    const targetY = structure.y + 2;
    const elementType = processor.getElementTypeAtCell(sourceX, sourceY);

    if (elementType === null || !processor.isCellEmpty(sourceX, targetY)) return;

    processor.commit([
      {
        kind: "remove",
        cellX: sourceX,
        cellY: sourceY,
        expectedElementType: elementType
      },
      {
        kind: "create",
        cellX: sourceX,
        cellY: targetY,
        elementType
      }
    ]);
  }
});

A processor commit is atomic: every mutation is validated before anything changes. Include expectedElementType on removals so a stale read cannot remove a different element.

Tech unlock

api.tech.registerNode("yourname.example-machine.tech", {
  name: "Example Machine",
  description: "Unlocks the Example Machine.",
  cost: 1000,
  branch: "logistics",
  icon: { spriteName: "example-machine" },
  unlocks: { structures: ["example-machine"] }
}, {
  parentId: 64
});

05 / Matter

Elements, particles, and terrain

Resolve stable string IDs once, then work with the numeric type returned by Sandkit:

const fireType = api.elements.getTypeFromId("fire");
const type = api.elements.getResolvedTypeAtCell(cellX, cellY);

if (type !== null && type !== fireType) {
  const definition = api.elements.getDefinitionByType(type);
  // definition.matterType can distinguish solids, liquids, gases, and more.
}
  • getTypeAtCell reads the literal cell type.
  • getResolvedTypeAtCell resolves a particle to its linked element type.
  • getInfoAtCell reports the type, particle state, cell ID, and element index.
  • getMatterTypeAtCell reports the broad matter category.

Elements are not terrain

Elements occupy the simulation and may move. Terrain is the durable world layer with types and optional HP. Use api.world.isTerrainAtCell or api.terrains.isAtCell before choosing the mutation family.

if (api.terrains.isAtCell(cellX, cellY)) {
  api.terrains.damageAtCell(cellX, cellY, 8);
} else if (api.fire.canBurnElementAtCell(cellX, cellY)) {
  api.fire.burnElementAtCellWhenIdle(cellX, cellY);
}

06 / Visuals & data

Assets and overrides

Mod-owned sprites

await api.sprites.loadFromMod(
  "yourname.machine",
  "assets/machine.png",
  { tint: 0xffffff }
);

Native texture overrides

"textureOverrides": {
  "conveyor_left": "assets/conveyor_left.png",
  "shaker_left": {
    "path": "assets/shaker_left_sheet.png",
    "frameWidth": 18,
    "frames": 6,
    "intervalMs": 166
  }
}

A string value replaces one static texture. An object declares an animated spritesheet with a fixed frame width, frame count, and interval.

Config overrides

"configOverrides": {
  "drill": "config/drill.json"
}

Overrides can conflict with other mods and game updates. Prefer targeted public API updates when the same result is possible.

07 / Maps

Custom map manifests

Maps combine image blueprints with explicit world metadata. The local schema supports terrain, lights, sensors, authorization, walls, light metadata, decor, and a JSON config layer.

"map": {
  "blueprints": {
    "terrain": "map/terrain.png",
    "lights": "map/lights.png",
    "sensors": "map/sensors.png",
    "authorization": "map/authorization.png",
    "wall": "map/wall.png",
    "lightsMeta": "map/lights_meta.png",
    "decor": "map/decor.png",
    "config": "map/config.json"
  },
  "width": 1920,
  "height": 1920,
  "spawn": { "x": 243, "y": 50 },
  "unstuck": { "x": 243, "y": 50 },
  "deployment": "skip",
  "topBounds": { "hard": 100, "soft": 275 },
  "depthLight": {
    "startY": 6500,
    "endY": 10070,
    "maxSize": 700,
    "minSize": 200
  },
  "parallax": { "widthScale": 1.5, "offsetY": -2600 },
  "colorMappings": { "4, 5, 6": "GoldSoil" }
}

Keep blueprint dimensions consistent with the declared map size, use the same coordinate system for spawn and unstuck locations, and validate color mappings against the terrain IDs you intend to paint.

08 / Advanced

Bundle patches

Patches modify compiled game bundles before execution. Use them only when the public API cannot express the change.

[
  {
    "id": "bundle-log-prefix",
    "file": "js/bundle.js",
    "find": "initializing workers",
    "operation": "insertBefore",
    "code": "[patched] ",
    "expectedMatches": 1
  }
]
  • find performs an exact string match.
  • regex accepts a pattern and flags.
  • Operations include insertBefore, replace, and wrap.
  • expectedMatches makes a changed bundle fail safely instead of patching the wrong location.
  • atomicGroup ties related patches together so partial application does not leave mixed behavior.

Patches are game-version sensitive. Keep match strings narrow, document why every patch exists, and retest after every Sandustry update.

09 / Performance

Performance patterns

  • Do not traverse an entire connected network once for every member. Cache topology and choose one coordinator.
  • Back off polling when a structure is idle or fully blocked, then restore the fast interval after useful work.
  • Resolve element IDs and stable definitions once instead of on every cell check.
  • Reuse arrays, masks, coordinate keys, and mutation objects in per-tick hot paths.
  • Read all inputs before committing if two routing directions could otherwise move the same element twice.
  • Use atomic processor commits to avoid partial moves and extra repair work.
  • Cap connected networks and area scans so malformed layouts cannot create unbounded work.

The Distributor example in this repository demonstrates topology caching, coordinator processing, bounded idle polling, reusable buffers, round-robin fairness, and simultaneous directional routing.

10 / Diagnostics

Debugging checklist

  1. Validate that modinfo.json is strict JSON—no comments or trailing commas.
  2. Confirm every relative path exists with the exact spelling and case.
  3. Check whether the method belongs to the main or worker API.
  4. For async sprite loading, confirm the entry is awaited.
  5. For mutations, confirm the simulation is idle or use the worker/processor-safe method.
  6. Record a load marker with api.storage.set so registration failures survive the loading screen.
  7. When a patch fails, compare its expected match count with the updated bundle before changing the patch.
api.storage.set("yourname.first-mod", "loadStatus", {
  version: "1.0.0",
  loaded: true,
  structureRegistered: true
});
